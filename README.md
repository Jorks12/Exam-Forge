# ExamForge

ExamForge е уеб приложение за самостоятелна подготовка и управление на изпити. Всеки потребител поддържа собствена банка и може да ползва общия каталог за X, XI и XII клас. Приложението генерира изпити със случаен или балансиран подбор, отчита резултатите по теми и предмети и планира преговор на сгрешени и пропуснати въпроси.

## Стек и структура

| Директория | Роля |
|---|---|
| `frontend/` | Next.js App Router, React, TypeScript, Tailwind CSS, Lucide и Recharts. Интерфейс на български. |
| `backend/` | Самостоятелен Express REST API. Zod валидация, подбор, оценяване и PostgreSQL транзакции чрез `pg`. |
| `database/` | SQL миграции, лични демонстрационни банки и общи банки за X, XI и XII клас. |
| `research/` | Синтетични данни, измервания, обобщения и графики. |
| `docs/` | Техническа документация, курсова работа и подготовка за защита. |

Next.js управлява Supabase сесията на сървъра и препраща заявките към Express с Bearer токен. Express проверява токена и се свързва с PostgreSQL. Тестът получава копие на текста и опциите при създаване. Ключът и обясненията се връщат при преглед на приключил опит.

## Инсталация

Необходими са Node.js 24 или по-нов, npm, проект в Supabase с включен вход по имейл и достъп до базата му. Изпълнете командите от корена на проекта.

```sh
npm ci
```

1. Отворете SQL Editor в предназначения за ExamForge проект в Supabase. Изпълнете веднъж съдържанието на [миграцията](database/migrations/001_examforge.sql) като собственик на базата. За автоматизирано изпълнение използвайте `psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/migrations/001_examforge.sql` в shell с конфигурирана променлива.
2. Копирайте `backend/.env.example` в `backend/.env` и `frontend/.env.example` във `frontend/.env.local`.
3. Задайте Project URL и publishable key и на двете места. В `backend/.env` задайте `DATABASE_URL` с connection string за мигрираната база. Използвайте Direct connection при IPv6 или Session pooler при IPv4. Запазете SSL проверката при отдалечена база. Ако драйверът изисква доверен сертификат, конфигурирайте CA от Supabase. Connection string съдържа парола и принадлежи само на Express.
4. Настройте `FRONTEND_ORIGIN` и `NEXT_PUBLIC_API_URL` според адресите на приложенията. За потвърждение по имейл настройте адреса `/auth/confirm`, шаблона и SMTP според [инструкциите за потвърждение](docs/email-verification.md).
5. След настройване на `backend/.env` приложете добавъчните миграции 002–006 с `npm run seed:catalogue -w backend -- --migrate-only`. Миграция [005_similar_questions.sql](database/migrations/005_similar_questions.sql) активира `pg_trgm` за търсене със сходни думи и проверка за вероятни дубликати. [006_shared_question_bank.sql](database/migrations/006_shared_question_bank.sql) позволява изпити от общата банка на администратора с отделни резултати за всеки потребител. При нова инсталация заредете учебните записи по процедурата по-долу.

За обичайно локално ползване отворете `Start-ExamForge.cmd`. Стартерът компилира frontend-а преди да отвори сайта, така че страниците са готови при първото посещение. За разработка с автоматично обновяване стартирайте в отделни терминали.

```sh
npm run dev -w backend
npm run dev -w frontend
```

Express слуша на порт 4000, а Next.js на 3000. Проверете `http://localhost:4000/api/health`. Отворете `http://localhost:3000` и се регистрирайте. При включено потвърждение отворете връзката от писмото. При липса на конфигурация фронтендът показва указание за настройка.

За продукционен build задайте публичните променливи преди компилация, след което стартирайте двата процеса.

```sh
npm run build
npm run start -w backend
npm run start -w frontend
```

## Зареждане на демонстрационна банка

След регистрация намерете UUID на тестовия профил в Authentication → Users. Изпълнете следната команда с неговия UUID.

```sh
npm run seed -w backend -- 11111111-1111-4111-8111-111111111111
```

Скриптът добавя 120 въпроса в четири теми за посочения профил. Повторно изпълнение със същия набор запазва редакциите и архива на вече внесените въпроси. Изберете четирите теми при създаване на изпит с 20 въпроса. При балансиран подбор демонстрационната банка позволява 5 въпроса от всяка тема и общи квоти 6, 10 и 4 по трудност.

## Училищен каталог

Училищният каталог в свързаната база съдържа 3600 активни въпроса в 36 банки. Всеки от 12-те предмета има по 100 въпроса за X, XI и XII клас. Общата банка на администратора съдържа отделни 250 въпроса. [Проверени бройки и разбивка по теми](docs/audit/EXAMFORGE_FINAL_AUDIT.md#8-банка-с-въпроси)

```sh
npm run seed:catalogue -w backend -- --check
npm run seed:catalogue -w backend
```

Първата команда валидира източниците и връща код 1 при непокрити квоти. Втората импортира проверените записи и отпечатва реалните бройки от PostgreSQL. Учебният обхват, източниците и форматът на файловете са описани в [документацията на каталога](docs/catalogue-bg.md).

## Проверки и експерименти

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run benchmark
```

За браузърния тест инсталирайте Chromium с `npx playwright install chromium`, след което изпълнете `npm run e2e -w frontend`. Може да използвате инсталиран Edge, ако зададете `EXAMFORGE_BROWSER_CHANNEL=msedge`. Тестът използва портове 3011 и 4011, тестов Auth HTTP сървър и вградена PostgreSQL база. Двете интеграционни проверки изискват локален loopback. За прегенериране на екранните снимки задайте `EXAMFORGE_SCREENSHOTS=1`.

Изпълнението на benchmark генерира наново файловете в `research/results` и `research/charts`. Времената зависят от средата. Прочетете [методиката](research/README.md) и [резултатите](research/results/summary.md).

## Демонстрация и ограничения

1. Създайте тема и въпрос. Филтрирайте банката по тема и трудност.
2. Заредете демонстрационните въпроси и създайте изпит с 20 въпроса. Изберете случаен подбор. Отговорете на част от въпросите и проверете след презареждане, че отговорите са записани.
3. Предайте изпита и разгледайте резултата, обясненията, историята и анализите.
4. Създайте втори изпит с балансиран подбор. След приключване сравнете целевите и действителните квоти.
5. Излезте и влезте отново. За проверка на изолацията опитайте да отворите копиран адрес на резултат с друг акаунт. Очаква се 404 от API.

Изпитът е за самоподготовка. Авторът на въпросите има достъп до собствената си банка. Изтеклите опити се оценяват при следващ достъп, включително от историята и анализите. Архивираните въпроси остават свързани с историята. Защитата на публичното внедряване зависи и от TLS, конфигурацията на Supabase и мрежовите ограничения.
