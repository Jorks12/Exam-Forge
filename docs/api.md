# REST API

Основният адрес по подразбиране е `http://localhost:4000/api`. Изпращайте JSON и `Authorization: Bearer <access-token>`, освен при здравната проверка. Успешните отговори са `{"data": ...}` с изключение на 204. Грешките са `{"error":{"code":"...","message":"..."}}`. Валидацията добавя `fields` с път и описание.

| Метод и маршрут | Вход и поведение |
|---|---|
| GET /health | 200 с `{"data":{"status":"ok"}}`. Проверява HTTP процеса. |
| GET /topics | Теми на текущия профил, включително общ и активен брой въпроси. |
| GET /grades | Поддържани класове с номер и име. |
| GET /subjects | По избор `grade`. Връща обхват, брой активни въпроси и брой теми по комбинация. |
| GET /subjects/:id | Каталожен предмет по slug, по избор ограничен с `grade`. |
| GET /subjects/:id/topics | `grade` е задължителен. Връща темите и активните бройки по трудност. |
| POST /topics | `name`, по избор `description` и `subjectGradeId`. Създава лична тема и връща 201. |
| PATCH /topics/:id | Частична промяна на име, описание и класификация. |
| DELETE /topics/:id | Изтрива празна тема и връща 204. При свързани въпроси връща 409. |
| GET /questions | `topicId`, `difficulty`, `active=true/false`, `search`, `page`, `limit`. Двойката `grade` и `subjectId` избира общия каталог. |
| GET /questions/counts | Активен брой и разбивка по трудност за същата комбинация от клас, предмет, тема и търсене. Без клас и предмет брои собствените въпроси. |
| GET /questions/:id | Подробности от собствената банка, включително ключа за редактиране. |
| POST /questions | `topicId`, `content`, `difficulty` 1–3, `options` с A–D, `correctLabel`, по избор `explanation` и `isActive`. Връща 201. |
| PATCH /questions/:id | Частична промяна. При промяна на `options` подайте и четирите. |
| DELETE /questions/:id | Архивира и връща 204. Възстановяване чрез PATCH с `isActive: true`. |
| POST /exams/generate | Приема конфигурацията по-долу. Създава опит и връща 201 с метаданни и разбивка по квоти. |
| GET /exams/:id | `attempt`, `server_now` и `items` без ключ и обяснение при активен изпит. При приключен опит елементите се преглеждат през резултата. |
| PATCH /exams/:id/answers | `itemId`, `optionId` от опциите на елемента или `null` за изчистване. |
| POST /exams/:id/submit | Оценява или връща вече финализирания резултат. Празно тяло. |
| GET /results/:id | Опит, статистика, тема и обратна връзка. При активен изпит връща 409. |
| GET /results | История, включително активни опити, с `page` и `limit`. |
| GET /analytics/overview | Брой приключили и предадени, средна и най-висока оценка, броячи и дял на верните отговори. |
| GET /analytics/topics | Име, брой въпроси, верни отговори и процент по теми. |
| GET /analytics/progress | До 50 последни оценени опита, подредени хронологично. |
| GET /analytics/subjects | Брой оценени опити и среден процент по предмет. |

Списъчните резултати за въпроси и опити съдържат `items`, `total`, `page` и `limit`. Страниците започват от 1. Размерът по подразбиране е 20, а максимумът е 100.

Каталожните въпроси са достъпни само за четене чрез API и се връщат без ключ или обяснение. Анализите приемат независими филтри `grade`, `subjectId`, `from` и `to`. Датите са включителни, във формат `YYYY-MM-DD` по часовата зона на София.

## Генериране

```http
POST /api/exams/generate
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "title": "Основи на програмирането",
  "topicIds": ["11111111-1111-4111-8111-111111111111"],
  "questionCount": 20,
  "algorithm": "balanced",
  "timeLimitMinutes": 30
}
```

`topicIds` приема от 1 до 30 уникални UUID. `questionCount` е от 1 до 100, а `timeLimitMinutes` е от 1 до 180. Методите са `random` и `balanced`. При успех `data.id` е UUID на опита. `data.allocation` съдържа цели и действителни бройки по теми и трудности. Случайният метод връща `null` за целевите квоти.

За общия каталог подайте `grade` и `subjectId`, например `11` и `math`. Можете да пропуснете `topicIds`, за да включите всички теми в комбинацията. По избор `difficulty` приема 1, 2 или 3. При зададено ниво балансираният подбор насочва квотата по трудност към него. Резултатът и историята връщат запазените метаданни в `attempt.catalogue` или `null` при личен опит.

```http
HTTP/1.1 422 Unprocessable Content
Content-Type: application/json

{"error":{"code":"INSUFFICIENT_QUESTIONS","message":"Налични са 7 активни въпроса."}}
```

## Запис на отговор

```http
PATCH /api/exams/22222222-2222-4222-8222-222222222222/answers
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "itemId": "33333333-3333-4333-8333-333333333333",
  "optionId": "44444444-4444-4444-8444-444444444444"
}
```

При успех 200 връща съхранения избор.

```json
{"data":{"itemId":"33333333-3333-4333-8333-333333333333","optionId":"44444444-4444-4444-8444-444444444444"}}
```

След крайния срок се връща 409 с `EXAM_EXPIRED`. Завършен изпит връща 409 с `EXAM_FINALIZED`. Заявка с опция от друг въпрос връща 422 с `INVALID_OPTION`.

Други статуси са 400 при невалидни полета, 401 при липсваща или невалидна сесия, 404 при липсващ или чужд ресурс, 429 при превишен лимит и 503 при недостъпна Auth услуга.
